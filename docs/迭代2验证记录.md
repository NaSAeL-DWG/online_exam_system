## 测试边界与实施次序

沿用已确认的 TDD 边界：真实 PostgreSQL / Redis 上的 HTTP API 集成测试，以及少量完整 Playwright 浏览器流程。每个垂直切片先观察预期失败，再实现并验证，不对内部函数调用进行 mock 式验收。

1. 共享题库：四类题目、判断 `false`、稳定 UUID 选项、筛选、版本冲突、关闭及不可变图片；前端安全渲染 Markdown、公式和代码块。
2. 预设试卷：挑题、调序、一位小数分值、共享编辑和归档；关闭题的新增限制与既有引用保留。
3. 考试快照：创建时复制、双向隔离、草稿编辑、发布校验、阅卷教师和乱序配置。
4. 资格和生命周期：限定名单按班与单独补入、去重、不联动、显式恢复、资格撤销审计；公开考试保留显式撤销规则。

主测试库为 `exam_test`，浏览器使用 `exam_dev`；使用项目独立 PostgreSQL 55432、Redis 16379，不修改系统 PostgreSQL 5432。API 使用 18000，前端使用 5173。用户在最终测试期间明确要求保留前后端预览，覆盖此前的关闭要求；完成后保留这些服务供查看效果。

## 与后续迭代的边界

- 学生考试列表、详情、首次开始、计时、提交和重试流程属于迭代 3，本轮不暴露不完整的学生开始 API。
- 整场取消属于实施计划迭代 3 的作答废弃链路，本轮不新增整场取消接口或按钮。
- 本轮建立真实的最小作答持久化边界及公开查询／废弃能力。撤回发布须查询所有历史作答，包含 VOID；不能以固定“无人开始”代替数据库查询。
- 撤销资格与现有作答废弃在同一事务完成；恢复资格不改变旧作答或已使用次数。阅卷任务尚未实现，其作废集成须在后续迭代补齐。
- PUBLIC 首次开始幂等建立资格由后续开始用例调用，不能绕过显式 CANCELLED 资格。AC04 的完整学生 HTTP 流程以及 AC20 的完整作答／任务链路留至迭代 3/4 验收。
- 本轮主要核对 AC02 的题库共享、AC03、AC05、AC06 和 AC27 的教师管理／图片访问部分；未实现的学生结果与分析接口不记为通过。

## 交付后修复：从站点首页登录未进入工作台

2026-09-26 用户从 `/login?redirect=/` 登录后未进入后台。真实浏览器复现中，后端健康检查和登录请求均为 200，但最终地址停在 `/`，工作台导航不存在。原因是根路径匹配到了没有默认子页面的登录布局；此前浏览器用例直接访问 `/login`，默认回跳 `/home`，没有覆盖首页回跳。

先新增 `root-navigation.spec.ts`，两个用例分别在根路径登录回跳、已登录后重开根地址时失败；再为 `/` 增加显式 `/home` 重定向，继续由现有身份守卫决定登录、首次改密或待审核页面。新增用例与教师首次改密、学生注册共 4 项通过，生产构建通过。随后以管理员和提供给用户的教师测试账号重跑原始 `/login?redirect=/` 路径，两者均登录 200 并显示工作台导航。未修改账号密码，前后端服务继续保留。
