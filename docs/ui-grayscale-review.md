# 灰度 UI 原型审核

首次交付：2026-11-03。最近更新：2026-11-04。

状态：用户已授权开始修改，第一轮 11 项意见均已在第 2 版灰度稿中落实并完成相关验证，等待用户复审。灰度稿尚未通过，配色尚未开始。

## 第一轮评审意见（2026-11-04）

以下按用户意见的出现顺序编号为 R1-01—R1-11，避免原消息中重复的“7”“8”造成歧义。页面名称统一采用原型中的“考试详情”“成绩详情”。本节保留评审要求；实际处理与验证结果见后文“第一轮处理结果”。

### R1-01：作答页的待检查标记

- 范围：学生 → 考试作答 → 正常状态。
- 要求：针对“标记待检查／已标记待检查”按钮，按钮常态使用灰度背景，已标记图标变为实心；已标记时使用白色文字与图标、深灰按钮背景。
- 验收：未标记与已标记可通过图标空心／实心、文字和按钮外观区分；已标记外观在鼠标移开后仍然成立。
- 已确认口径：用户在授权修改后明确选择“白色文字与图标，深灰按钮背景”。

### R1-02：考试详情增加横向信息卡片

- 范围：学生 → 考试详情 → 考试信息区域。
- 要求：增加一排三张信息卡片，依次为“考试状态”“作答时长”“试卷结构”。
- 第一张卡片：未开始时，大字显示距开始时间，例如“距离考试开始还有：1 小时 32 分钟”；进行中时显示距离考试结束的时间。倒计时底部展示完整考试时间，例如“2026 年 11 月 05 日 14 点—16 点”。这里表达整场考试的开始／结束时间，与作答页的个人作答截止时间区分。
- 第二张卡片展示作答时长；第三张卡片展示试卷结构。
- 考试结束后，三张卡片全部呈灰色不可答状态。灰度稿需通过明度、强调程度及状态文案体现这种区别；后续配色稿仍使用中性灰表达结束状态。
- 原有考试信息栏保留，作为“详细信息”栏继续存在，不能被新卡片替代。
- 验收：未开始、进行中、已结束三种状态含义明确；倒计时与底部考试时间对应；三卡与原详细信息同时可见。

### R1-03：加载占位条增加白光流动效果

- 范围：学生 → 我的考试 → 加载中，以及其他页面相同类型的加载占位条。
- 要求：灰色占位条增加呼吸白光流动效果。每隔一段时间，一段较短的渐变白条从左侧出发，快速移动到右侧并消失，然后间隔重复。
- 验收：灰色底条持续存在；白光为局部短条，具有移动、消失与间隔，不表现为整块占位区域同时闪白；同类占位条使用一致效果。

### R1-04：作答页身份展示与退出提醒

- 范围：学生 → 考试作答 → 右上角身份和退出操作。
- 要求：姓名旁同时显示学号；“退出工作区”改为“退出作答界面”。
- 退出前增加提醒弹窗，说明未提交的作答仍会保留、退出不会暂停计时、到截止时间将自动提交。措辞需明确自动提交使用已保存到服务器的答案，避免把尚未保存的本地输入描述成已被保留。
- 弹窗按钮固定为“我已知晓”“返回作答”；前者确认退出作答界面，后者关闭弹窗并留在当前作答。
- 验收：姓名与学号同时可识别；点击退出先出现提醒；两按钮去向明确；退出界面不被表达为立即交卷。

### R1-05：保存中的图标改为循环加载

- 范围：学生 → 考试作答 → 正在保存，位置为 `question-footer` 保存指示。
- 要求：使用循环加载图案替代对勾。
- 验收：保存中展示循环加载图案；对勾只表达保存完成，不能与“正在保存”文字同时出现。

### R1-06：下拉选项统一为 CSS 设计样式

- 范围：全部下拉选择控件，包括页面中的筛选、表单和评审切换控件。
- 要求：用 CSS 制作风格一致的下拉栏，统一收起状态与弹出选项区域的视觉表现。
- 验收：各处下拉控件的边框、间距、箭头、选中项及弹出列表保持同一设计规则；与 R1-09 的焦点边框和弹层阴影一起验收。

### R1-07：成绩详情提示区域按内容适应高度

- 范围：学生 → 成绩详情 → 待批改、结果未公布场景。
- 问题：“最后一次作答正在批改”等 notice 提示区域留有较大空白。
- 要求：提示区域高度适应实际内容，不因相邻区域或网格布局而被不必要地拉高；结果未公布场景同步处理。
- 验收：两个场景均保留必要内边距，正文之后不出现大块无意义留白。

### R1-08：错题增加掌握情况筛选

- 范围：学生 → 我的错题。
- 要求：增加掌握情况筛选。按现有状态提供“全部”“待复习”“已掌握”等对应选项。
- 验收：选择掌握情况后仅展示匹配记录；可与原搜索、科目等筛选共同使用；清除筛选后恢复对应记录。

### R1-09：输入框焦点与下拉弹层阴影

- 范围：所有输入控件，包括文本框、数字框、密码框、多行输入框及下拉选择控件。
- 要求：获得焦点时强调控件自身边框，不在外侧另加一圈焦点边框。下拉控件的弹出选项区域，在统一边框基础上另加一圈阴影。
- 验收：焦点由控件自身边界清楚表达，不出现外侧双重边框；下拉弹层具有阴影，普通输入框不因此增加阴影；键盘操作仍能识别当前焦点。

### R1-10：核对管理员的阅卷入口与角色职责

- 范围：管理员账号的导航和可预览功能。
- 用户问题：“管理员账号为啥会有阅卷。”
- 已确认口径：用户明确选择“移除阅卷工作台和评分入口，保留考试管理与阅卷进度”。
- 验收范围：管理员导航、评审页面选项、工作台卡片、考试详情操作均不提供一线评分入口；考试管理与阅卷进度仍可访问。
- 当前状态：原型入口已按上述范围修改；生产前端和后端权限不在本轮修改范围。

### R1-11：学生注册表单居中并限制宽度

- 范围：公共页面 → 学生注册。
- 问题：“返回登录”与表单距离过远，页面内容被拉到容器边界。
- 要求：注册页面采用居中布局；表单卡片设置最大宽度，不强行铺满可用边界；“返回登录”与表单保持接近，在同一局部布局中组织。
- 验收：宽屏下表单宽度受限、整体居中，返回登录入口靠近表单；窄屏下卡片适应窗口且不溢出。

### 本轮执行边界

- 用户先要求只记录，随后以“开始”授权实施，并明确 R1-01、R1-10 两项口径。
- 修改仅限独立的灰度 HTML 原型及设计文档；不修改生产前端、后端权限或业务数据。
- 第 2 版完成后仍需用户复审灰度稿，通过后才进入配色。

## 打开与操作

交付文件：[grayscale.html](../design/ui-redesign/grayscale.html)。在本地浏览器中直接打开即可使用，无需后端、构建、网络连接或额外资源。

顶部深色横条是评审控制区，不属于生产界面。使用其中的“角色”“页面”“场景”切换视图，也可沿页面中的按钮操作。HTTP 预览时 URL 会保存当前视图和场景；直接打开本地文件时不修改 URL。刷新会重置答案、评分和其他演示修改。

所有姓名、考试与记录均为虚构数据。倒计时为固定场景示例；保存、发布、交卷等操作只修改当前页面内存，不访问实际业务系统。部分次要列表采用固定示例详情；本稿用于审核布局、状态和交互位置，不作为完整业务实现验收。作答采用 5 种代表题目内容展示 20 个答题位置；组卷使用少量示例题验证选题、排序与设分。

## 推荐审核顺序

1. 学生：考试工作台 → 我的考试 → 考试详情 → 考试作答 → 交卷完成。
2. 作答页切换时间预警、保存中、保存失败、其他页面已接管、长题干与图形，检查常态与异常的视觉权重。
3. 学生：考试历史 → 成绩详情 → 答卷回看 → 错题与学习分析，检查待批改、未公布、受限回看等状态。
4. 教师：考试管理 → 考试配置与名单，区分发布考试和公布结果；再查看题库、组卷、阅卷与评分。
5. 管理员与公共页面：检查表格、表单、空态、错误、确认弹窗是否沿用相同规则。
6. 缩窄窗口，检查长题目阅读、答题卡展开、导航抽屉和局部表格滚动。

## 请审核的内容

- 第一眼能否识别当前考试、状态与下一步操作。
- 作答区和评分区是否足够突出，辅助导航是否克制。
- 常态计时与保存反馈是否清晰；异常提示是否获得足够强调。
- 小圆角、边界、字重和留白是否符合“锐利、严肃”的方向。
- 桌面和窄屏的阅读密度是否合适。

反馈建议采用“页面／场景 + 问题 + 希望的调整”。本阶段审核布局与灰度层级。只有用户明确通过灰度稿，才制定最终色相并制作配色 demo。
