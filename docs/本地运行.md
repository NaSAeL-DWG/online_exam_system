# 本地运行与运维

本说明涵盖已交付的身份基础及正在实施的迭代 2，实际能力以[实施计划](./实施计划.md)为准。命令使用 Bash（Windows 可用 Git Bash）。不要把示例凭据用于实际环境。

## 环境与端口

需要 Node.js、npm、Python、uv、PostgreSQL 和 Redis。本次运行使用 Windows Node 24.12.0、npm 11.6.2、uv 0.10.7、Python 3.13.14、PostgreSQL 18.3，以及 WSL Ubuntu 24.04 中的 Redis 8.8.0。系统另有 Python 3.14；后端独立虚拟环境使用 3.13，避免原生驱动版本不兼容。

| 进程 | 本次本地端口 | 说明 |
|---|---|---|
| PostgreSQL | 55432 | 独立实例，开发库 `exam_dev`、测试库 `exam_test`；未修改原有 5432 服务 |
| Redis | 16379 | 独立密码保护实例；开发 DB 0、测试 DB 15 |
| FastAPI | 18000 | 本机 8000 已被其他软件占用 |
| Vite | 5173 | `/api` 代理至 FastAPI，同源 Cookie |

其他机器可以使用 PostgreSQL 5432、Redis 6379，按实际地址修改 `.env`。数据库和 Redis 用户、密码、库名必须由运行环境提供。测试库必须与开发/业务库分离，不要让测试清理业务数据。

## 后端

在 `backend/` 中安装锁定依赖，复制环境样例，填写真实配置，然后执行迁移与管理员初始化：

```bash
cd backend
uv sync --locked --python 3.13
cp .env.example .env
# 编辑 .env 后再继续；已有 .env 时不要覆盖。
uv run alembic upgrade head
uv run python -m app.cli init-admin
uv run uvicorn app.main:app --host 127.0.0.1 --port 18000
```

管理员只通过本地命令创建；网页不提供新增管理员入口。初始化使用环境中的管理员账号、姓名、邮箱、手机号和密码。真实密码不放在命令行参数或 Git 中。

API 文档位于 [本地 Swagger](http://127.0.0.1:18000/docs)，存活检查为 [health](http://127.0.0.1:18000/api/health)。存活检查仅代表 API 进程可访问，数据库和 Redis 是否可用以实际业务请求为准。

## 前端

另开终端：

```bash
cd frontend
npm ci
npm run dev
```

打开 [本地页面](http://127.0.0.1:5173)。使用同一主机名访问前端，避免在 `localhost` 与 `127.0.0.1` 之间切换造成 Cookie 不一致。生产构建使用 `npm run build`。

## 身份演示流程

1. 使用初始化管理员登录，创建教师并设置临时密码。
2. 教师首次登录先修改密码，再进入审核和班级页面。
3. 学生注册并登录，仅可查看审核状态、必要资料和申请；被拒绝后可修改资料重新申请。
4. 教师审核通过后，学生获得普通业务入口。学生考试列表和作答按迭代 3 实现。
5. 管理员创建教学班，关联一位或多位教师；管理员或关联教师维护已激活学生，学生可加入多个班级。
6. 管理员停用账号或人工重置密码，旧会话立即失效；临时密码登录仍需先改密。

邮箱和手机号验证接口返回 `501 VERIFICATION_NOT_ENABLED`，第一版没有验证码发送或自助找回。联系方式修改需要当前密码。

## 题库图片存储

教师和管理员可上传静态 PNG、JPEG、WebP，默认最大 5 MiB；服务端验证实际图片内容，不仅检查扩展名。`ASSET_MAX_BYTES` 控制大小，`ASSET_STORAGE_DIR` 默认为相对后端工作目录的 `../.local/uploads`，其他部署应使用明确的持久目录。

图片由服务端生成存储名，以独占方式创建，不覆盖同名文件。数据库保存资源元数据，备份或迁移须同时保留 PostgreSQL 和图片目录；不要把上传目录配置成公开静态目录，也不要按“当前题库未使用”直接清理图片，历史快照仍可能引用。数据库提交失败可能留下不可访问的孤立文件，本轮没有自动清理任务。

图片经 `/api/assets/{id}` 实时鉴权，返回 `private, no-store` 和 `nosniff`。迭代 2 只开放教师／管理员读取；学生题干图片须在迭代 3 接入快照引用授权，解析图片须在后续同时校验结果公布及允许回看。

## 教师考试准备流程

1. 进入共享题库，创建单选、多选、判断或简答题，填写科目、难度及知识点。题干和解析可预览 Markdown、公式及上传图片；选择题选项 ID 在编辑中保持稳定。其他教师可读取和编辑同一资源，版本冲突须重新加载后处理。
2. 在共享试卷中挑题、调序并设置一位小数分值。关闭题不再出现在可新增题目中，原试卷关联仍保留；归档试卷不能创建新考试。
3. 从试卷创建考试，立即形成独立快照。可以用同一试卷创建两场考试，之后修改题库或试卷不影响既有快照；编辑考试草稿也不会回写来源。原试卷含关闭题时显示复制提示。
4. 编辑考试时间（上海时区）、时长、次数、多选评分、题目／选项乱序、及格百分比及回看开关。含简答题时，发布须至少有一名仍激活的指定阅卷教师。
5. 限定考试可以按班级当前成员或单独选择学生补入，合并去重。此后班级变化不联动考试资格；再次补入已撤销的资格会提示显式恢复。撤销和恢复保留审计，恢复不改变历史作答与已用次数。
6. 保存草稿后发布考试。发布锁定题目和配置；只有完全没有历史作答记录时可撤回发布再编辑，包括已有废弃作答的考试也不能撤回。本轮只完成教师准备流程，学生实际开始／作答及整场取消按实施计划迭代 3 开放。

管理列表沿用 `page`、`page_size`、`q` 参数和 `items`、`total`、`page`、`page_size` 响应；详情直接返回明确 DTO，分值用十进制字符串传输。资格使用自己的 `version`，不会用考试版本替代个人资格的冲突检查。

## 安全配置与恢复

本地开发必须显式采用开发配置才允许 HTTP Cookie。生产必须使用 HTTPS、Secure Cookie 和独立随机 JWT 密钥。登录凭据由 HttpOnly Cookie 保存，写请求携带 CSRF Header。Redis 不可用时返回可重试错误，不降级为免认证访问。

管理员忘记密码时，在本机更新环境中的管理员密码后执行：

```bash
cd backend
uv run python -m app.cli reset-admin
```

命令修改密码、递增认证版本并撤销旧会话。普通学生/教师通过管理员页面人工核验后重置。停用账号与审核状态分开处理；恢复待审核账号不能跳过审核。

### 提交后的会话清理恢复

账号、密码或联系方式变更与必要的会话清理任务在同一个 PostgreSQL 事务中保存。数据库已提交而 Redis 暂时不可用时，API 仍返回业务成功，并通过 `X-Session-Cleanup: pending` 提示清理待处理。此时不要重复提交修改；认证仍检查数据库状态和 `auth_version`，旧身份不能利用清理延迟继续访问。

恢复 Redis 后运行本地维护命令：

```bash
cd backend
uv run python -m app.cli retry-session-cleanups --limit 100
```

命令返回 `attempted`、`completed`、`pending`、`failed` 计数。清理失败的任务保留重试次数、最近尝试时间及错误类型；日志不记录连接凭据。`pending` 非零时继续处理或检查 Redis 可用性。清理按认证版本执行，不撤销重置密码后新建立的会话，也不重复写入业务审计。

刷新凭据在数据库校验完成后才原子轮换。轮换前的数据库故障可以使用原凭据重试；最终轮换已完成但响应丢失时，不保证透明恢复，旧凭据重放会使会话失效，需重新登录。

迁移回退仅用于空的、可重建的测试/开发库：`uv run alembic downgrade base` 将删除本迭代表及数据；有需要保留的数据时先备份并评估回退。业务启动不会自动建表或清空数据。

## 测试

HTTP 集成测试必须显式提供独立 PostgreSQL/Redis 测试地址。本次会话的私有配置保存在 `.local/backend-test.env`，未提交：

```bash
cd backend
set -a
source ../.local/backend-test.env
set +a
uv run python -m pytest -q
```

在其他机器上设置 `TEST_DATABASE_URL` 和 `TEST_REDIS_URL` 为专用测试实例后运行同一命令。测试应检查公开 API 行为，不以 SQLite 替代 PostgreSQL。

前端真实流程测试需要已启动的 API、已迁移开发库和初始化管理员：

```bash
cd frontend
npx playwright install chromium
# 从私有环境配置加载 E2E_ADMIN_LOGIN、E2E_ADMIN_PASSWORD。
npm run test:e2e
```

实际执行版本、红绿证据及验证范围见[迭代 1 验证记录](迭代1验证记录.md)。ARQ worker、考试到期扫描和评分队列将在迭代 3/4 实现，本迭代无需启动 worker。

## 当前工作区的隔离服务

本次已在 `.local/pgdata` 初始化独立数据库，并将随机凭据写入未跟踪的私有配置。无需使用现有 PostgreSQL 服务的管理员密码。若开发服务已停止，在项目根目录重新启动 PostgreSQL：

```bash
/d/postgresql/bin/pg_ctl.exe \
  -D D:/codex_workspace/online-exam-system/.local/pgdata \
  -l D:/codex_workspace/online-exam-system/.local/postgres.log \
  -o '-h 127.0.0.1 -p 55432' -w start
```

另开终端以前台方式运行独立 Redis；该配置启用密码，使用与现有 WSL Redis 不同的端口：

```bash
MSYS_NO_PATHCONV=1 wsl -d Ubuntu-24.04 -- redis-server \
  /mnt/d/codex_workspace/online-exam-system/.local/redis.conf
```

Redis 终端使用 Ctrl+C 停止；PostgreSQL 使用下面命令正常停止，保留数据目录：

```bash
/d/postgresql/bin/pg_ctl.exe \
  -D D:/codex_workspace/online-exam-system/.local/pgdata -m fast -w stop
```

这些路径仅适用于当前机器；其他机器应按自身安装路径配置服务及 `.env`。不要提交 `.local`、数据库目录、密码文件或测试报告中的会话信息。
