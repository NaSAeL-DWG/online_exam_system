# 一键生成演示数据

如果你想快速向他人演示本系统，或者想在本地拥有一套涵盖各种考试状态、成绩、错题和阅卷任务的完整数据，不需要手动注册十几个账号去点点点——直接运行内置的 `app.demo` 模块即可。

**它的工作原理很干净：**
- 完全通过系统公开的 HTTP 接口走真实业务流程（真实注册、审核、建题、组卷、开考、答题、交卷、判分、公布），**绝不绕过权限直接篡改数据库时间戳，也没有留任何后门接口**。
- 所有数据都带有独立的**命名空间（Namespace）**前缀，不会清空你数据库里已有的数据，而且支持中断后续跑。

---

## 1. 准备工作与运行命令

在运行演示脚本前，请先按 **[快速启动指南](quick-start.md)** 完成数据库迁移、初始化管理员，并确保 **后端 API** 和 **ARQ Worker** 正在运行。

### 第一步：准备私有环境变量文件

在仓库的 `.local/demo.env`（已被 Git 忽略）中写入以下 3 个变量：

| 变量名 | 说明 |
| :--- | :--- |
| `DEMO_ADMIN_LOGIN` | 已初始化的系统管理员登录名（不填则自动回退读取 `ADMIN_LOGIN_NAME`） |
| `DEMO_ADMIN_PASSWORD` | 系统管理员密码（不填则自动回退读取 `ADMIN_PASSWORD`） |
| `DEMO_PASSWORD` | **必填**：为你即将生成的演示教师和演示学生统一设置的登录密码（需满 10 位） |

> **安全提醒**：包含特殊字符的密码请用引号包裹好，写成 Bash 可 `source` 的格式；不要把真实密码直接写在命令行参数里。

### 第二步：执行演示数据生成命令

在仓库根目录下打开终端（Git Bash）：

```bash
cd backend
set -a
source ../.local/demo.env
set +a

uv run python -m app.demo \
  --base-url http://127.0.0.1:18000 \
  --namespace demo-v1 \
  --manifest ../.local/demo-v1.json \
  --window-seconds 120
```

**运行过程说明：**
- 因为脚本走的是真实限时考试流程，它需要**真实等待短考试时间窗口结束**才能触发后续的收卷、阅卷和公布成绩，所以命令跑完通常需要几分钟，请耐心等待。
- `--window-seconds` 控制短考试窗口时长（默认 120 秒，最低不能少于 30 秒；如果电脑性能较慢建议调大）。
- 如果你只想先生成老师、学生账号和教学班，其他自己手动操作，可以加上 `--stage identities`；之后想补齐完整考试数据时，用相同的 `--namespace` 和 `--manifest` 再跑一次完整命令即可。

## 2. 生成了哪些数据？怎么按顺序演示？

命令跑完后，终端会打印出生成的账号清单（不会打印密码和答案）。你可以在输出里找到代号 `t1` ~ `t3`（教师）和 `s1` ~ `s6`（学生）对应的实际登录账号（`login_name`），密码统一使用你在 `DEMO_PASSWORD` 里设置的密码。

### 内置演示场景一览表

| 生成的数据对象 | 你能用它演示什么核心亮点？ |
| :--- | :--- |
| **3 名教师、6 名学生、2 个教学班** | 多名教师共管班级、一名学生加入多个班、缺考统计、撤销考试资格等组织场景 |
| **4 类题型题库 + 100 分标准试卷** | 单选/多选/判断/简答混排、Markdown 与公式渲染、试卷复用与考试独立快照 |
| **已公布成绩的限定考试** | 演示“多次作答取最后一次有效提交”：即使第二次考得比第一次低，最终成绩也严格取最后一次 |
| **已公布成绩的公开考试** | 演示公开考试无固定应考分母的统计口径，以及学生的答卷回看与错题自动归集 |
| **已公布但禁止回看的考试** | 演示权限边界：学生能查到自己的总分，但点不开答卷详情、标准答案、解析和细分错题 |
| **最后一次作答待批改的考试** | 演示严谨成绩状态：最新一次交卷还没批完时，最终成绩显示“待批改”，绝不拿上一次的旧分顶替 |
| **正在撤回更正中的考试** | 演示教师撤回已公布成绩后，学生端同步隐藏成绩、错题与学习分析的安全机制 |
| **被撤销资格 & 整场取消的考试** | 演示异常处置：相关答卷自动作废（Void），保留审计痕迹但不污染正常统计 |
| **当前可作答、未开始与草稿考试** | 留给你在现场亲手演示：学生点开始答题、自动保存、交卷，或教师现场修改草稿并发布 |

### 推荐现场演示路线

1. **先登教师账号（如 `t1`）**：看教师工作台的待阅提醒 → 看题库与试卷 → 点开已公布考试看成绩分布图表 → 点开待批改任务现场演示简答题打分。
2. **再登学生账号（如 `s1`）**：看学生工作台的倒计时卡片与双栏概览 → 去“考试历史”对比允许回看、禁止回看、待批改三种成绩状态 → 去“我的错题”添加复习笔记并标记已掌握 → 看“学习分析”趋势图 → 最后进入“当前可作答考试”现场答题交卷。
3. **最后登管理员账号**：查看全局阅卷进度、演示改派阅卷任务，并打开“系统日志”展示刚才一系列操作留下的实时运行日志与安全审计记录。

## 3. 中断续跑与重新生成

- **断点续跑**：`.local/demo-v1.json`（Manifest 清单文件）记录了每一步生成的对象 ID。如果中途中断，保持相同的 `--namespace` 和 `--manifest` 重新运行，脚本会自动跳过已完成的步骤继续往下走，不会重置已有分数或覆盖你手工填写的笔记。
- **开新的一轮演示**：由于可作答考试会随着真实时间流逝而自然截止，重跑同一个命名空间不会给已经截止的考试“无限续期”。当你需要一批全新的实时可考数据时，直接换一个新的命名空间（比如把 `demo-v1` 改成 `demo-v2`，同时换个 manifest 文件名）再跑一次即可。
- **环境隔离**：系统不提供一键删库后门，请只在开发库或专用演示库上运行此工具，不要往真实生产教学库里灌入演示账号。
