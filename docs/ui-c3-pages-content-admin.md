# C3 内容准备与系统管理逐页落实

本轮以 `design/ui-redesign/color.html` 中 `questionsView`、`questionEdit`、`papersView`、`paperEdit`、`accountsView`、`classesView`、`approvalsView`、`logsView` 为结构基准。页面继续调用现有 API，未把原型示例记录写入应用。

## 逐页变更

| 页面 | 原有差异 | 本轮落实 | 业务适配 |
| --- | --- | --- | --- |
| 共享题库 | 筛选、列表标题嵌套同一面板；题型与难度混在其他列 | 独立筛选区、六列表格、题干下显示实际题目 ID、统一表格页脚 | 保留科目、题型、难度、知识点、状态五项服务端筛选、搜索、分页和错误重试；状态仍显示实际使用中/已关闭 |
| 题目编辑 | 编辑器为宽模态框，分类横排，编辑与预览等宽 | 页级编辑标题与返回入口；主栏科目/题型、题干、答案、解析，侧栏题目属性、变更范围与预览 | 保留四题型、动态选项、正确答案、Markdown/公式、图片上传、字段校验、版本冲突、关闭确认及未保存保护；实时预览是已有必要功能，在属性侧栏延续稿风格 |
| 共享试卷 | 筛选嵌在列表面板内，题量与总分拆列 | 独立搜索、试卷标题/说明、题量与总分合列、编辑组卷入口 | API 不提供列表科目与最近更新时间，因此保留真实状态列，不推测科目与更新时间 |

| 账号管理 | 冗余目录标题/说明、角色切换胶囊、姓名头像 | 标题眉题、独立搜索/角色下拉、姓名账号主次层级、记录表格和页脚 | API 不含账号所属教学班，不伪造班级列；保留教师创建、资料更正、状态确认和人工重置密码 |

| 学生审核 | 联系方式常驻表格，行内直接通过/拒绝 | 按稿展示学生、学号、申请时间、状态；先打开“审核资料”核验弹窗 | 核验弹窗显示实际联系方式与申请时间；通过、带原因拒绝及已处理资料查看保留；继续使用服务端搜索与分页 |
| 系统日志 | 复杂筛选占整块面板，日志以连续控制台文本展示 | 独立关键词/模块主筛选、高级筛选折叠、时间/级别/模块/记录四列呈现、可展开详情 | 操作审计切换时展开对应高级条件；保留时间范围、累计等级规则、任务/关联ID、操作者/对象筛选、实时刷新、跟随/历史锚点、导出与采集设置 |

## 实现边界

- `QuestionFields` 的页级布局通过可选 `pageLayout` 启用；考试快照等原有使用方保持原布局和业务行为。
- 试卷列表没有原型中的科目和最近更新时间，账号没有教学班，教学班没有年级。这里沿用已有真实字段，未额外发起全量列表请求拼凑关联信息。
- 题库原型展示单一科目筛选，但实际必须保留的五项筛选按同一输入样式排列。日志高级查询、选题与实时预览等原型未覆盖功能使用相同表单、表格、侧栏和弹窗样式。
- 移动端保留真实表格列数并在表格内部横向滚动；编辑双栏改为单栏，页面本身无水平溢出。
