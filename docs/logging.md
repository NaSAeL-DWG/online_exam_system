# 系统日志

已激活的系统管理员可从工作台进入“系统日志”（`/admin/logs`）。教师、学生及未登录用户不能查询、下载或修改日志设置。运行日志与操作审计分开查看，筛选和下载都由后端验证权限。

## 查看与筛选

运行日志支持时间范围、模块、任务、关键词和关联标识筛选。操作审计支持操作者、操作类型、对象类型和对象标识筛选。日志使用统一文本格式：

```text
2026-11-02T14:23:08.126+08:00 INFO: [exam](发布考试): 考试发布成功
```

等级筛选是以下累加规则，**不是常见的“只显示该等级及更严重日志”**：

| 选择 | 显示 |
|---|---|
| INFO | INFO |
| WARNING | INFO、WARNING |
| ERROR | INFO、WARNING、ERROR |
| DEBUG | 全部已采集等级 |

自动刷新与自动滚动默认开启，每 3 秒读取更新。向上翻阅时暂停跟随，使用“回到最新”继续跟随。历史内容分页读取，页面只保留有限数量的日志，避免长时间浏览耗尽内存。切换筛选不会让迟到的旧请求覆盖新结果。

页面时间按浏览器本地时区显示，展开详情可见原始带时区时间；下载保留服务器的带时区格式。在线记录在新增和清理期间会变化，分页查看不是冻结快照。

普通读取、日志页轮询、空扫描和运行细节归入 DEBUG。选择 DEBUG 只改变查看范围；若需要更多内部细节，在管理区按模块开启临时采集，15 分钟自动到期，也可提前关闭。该设置对全体管理员可见，并作用于使用同一数据库的应用进程。

## 在线保留与文件记录

| 文件设置 | 在线运行日志 | 服务器日志文件 |
|---|---|---|
| 关闭（初始默认） | 最近 20000 条，不按 7 天清理 | 不新增、不追加 |
| 开启 | 最多 100000 条，同时不超过 7 天 | 单个 10 MiB，含活动文件最多 5 个 |

文件开关是持久化的系统级设置，重启后保持上次状态。关闭后在线记录收缩至最近 20000 条；已有日志文件保留，重新开启不会恢复已清理的在线记录。

文件目录由 `LOG_STORAGE_DIR` 配置，默认 `../.local/logs`（相对于后端工作目录）。API、worker 和 CLI 必须指向同一可写目录。数据库锁用于协调写入次序；它不会自动把不同机器的本地目录变成共享文件系统，多主机部署需要显式配置共享目录。

关闭文件记录仍会将有限运行日志保存到 PostgreSQL，因此重启后可以继续查询。操作审计与运行日志独立保存，不按此处的数量和时间规则删除。管理员页面只显示安全摘要，不暴露原有审计中的联系方式、答案、解析或完整前后值。

Windows 快速启动脚本不再另存 API、worker 的控制台输出，避免绕过文件开关；PostgreSQL、Redis 与前端开发工具的诊断输出仍由各自启动方式管理。应用启动失败、尚不能访问日志页时，可按[快速启动](quick-start.md)在前台运行 API 或 worker，查看启动错误。

## 下载与安全

“下载日志”导出当前视图、当前筛选范围的 UTF-8 `.log` 文件，独立于服务器文件开关。每次最多 10000 条；超出时需缩小时间或其他筛选范围，不会只下载当前页或静默截断。

文件设置、临时 DEBUG 设置和下载行为都会留下操作审计。API 位于 `/api/admin/logs`，下载使用带 CSRF 校验的 POST。日志响应禁止缓存。日志不包含密码、令牌、完整请求正文、学生答案和标准答案；异常不会采集局部变量。不要主动将这些内容写入日志消息或命令输出。

## 开发与维护

后端继续采用现有模块化三层结构。日志查询、配置及导出用例属于日志模块；跨模块审计读取通过身份模块的公开查询能力完成。运行日志写入使用独立事务，避免日志故障回滚业务操作；业务审计仍与对应业务事务共同提交。

新增采集点应提供稳定模块名、任务名及必要的请求／任务关联标识。普通操作记录结果与对象标识，不记录输入正文。需要输出到文件的应用进程必须使用统一日志配置及相同的文件目录，不另行安装独立文件处理器。

可在 `backend/` 中执行 `uv run python -m app.cli logging-check --module cli --count 1`，发送固定安全诊断记录并在管理员页面筛选 `cli` 模块确认采集。它不接受业务正文；批量参数用于独立测试环境，不应在业务环境大量制造记录，以免挤出有用的历史。

日志队列每个进程最多容纳 5000 条，每批最多 200 条。存储故障或队列溢出时，诊断记录可能被丢弃；恢复后的成功批次会记录丢弃数量。硬崩溃可能丢失尚未落库的队列内容，文件和数据库也不是原子双写。必要业务审计仍与业务事务共同提交，不受运行日志缓冲策略影响。

大量历史审计首次建立读取序号时分批补齐，每批最多 1000 条，因此在线列表可能短暂处于追平状态；导出直接查询已提交审计，不受补齐进度影响。

迁移、配置和相关测试说明见[运维指南](operations.md)、[测试与验证](testing.md)。运行日志属于有界诊断记录，不能代替业务数据、审计记录和备份。
