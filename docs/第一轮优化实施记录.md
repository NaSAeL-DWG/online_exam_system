## 接口约定

- 列表使用 `page`、`page_size`、`q`，响应含 `items`、`total`、`page`、`page_size`；角色、状态过滤保留。班级详情按需返回该班成员。
- 数据库写入成功但 Redis 清理未完成时，保留业务成功状态，通过 `X-Session-Cleanup: pending` 表明持久补偿待处理。前端不得因此重复提交已完成操作。
- 账号重置后的延迟补偿只撤销旧认证版本会话，不应清理随后使用新密码建立的新会话。
- 轮换前数据库故障应允许使用原凭据重试；轮换最终成功后的网络交付失败有明确限制，不承诺完全无感恢复。

## 运维与边界

- 新迁移为 `0002_session_cleanup`，没有重写已交付的 0001。已有用户、资料、班级和审计表保留。
- Redis 恢复后通过 `uv run python -m app.cli retry-session-cleanups --limit 100` 执行持久补偿；本轮没有引入定时后台 worker。若持续发生失败，运维需检查 Redis 并重新执行命令，不能把待处理状态描述为已自动恢复。
- 轮换最终成功后的网络丢失不提供旧凭据重放恢复；前端需明确提示重新登录。该限制与轮换前数据库故障可重试是不同情况。
- 列表查询数固定不等于已完成吞吐或 100 人并发压测；本轮没有作此性能承诺。
- 旧实现按项目规则移动到忽略的 `.deletedfiles/backend-round1/`；`app/config.py`、`app/db.py`、`app/models.py` 仅保留兼容导出或迁移模型注册，业务规则不在这些旧入口继续扩展。
- 前端错误验证包含：真实改密后连接中断、成功但清理待处理、联系方式写入后响应 JSON 损坏、刷新响应丢失、轮换前 503、退出时 503。成功待清理不提示重复改密；不确定写入先重新登录或读取状态；退出失败不伪装已退出。
- 班级列表及教师／学生候选使用服务端分页，班级详情的已有成员仍按需一次读取。前端翻页与搜索保留已选成员的名称及 ID，不预拉全部候选。
