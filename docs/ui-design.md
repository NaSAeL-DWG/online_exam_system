# UI 改版设计约束与验收流程

状态：文字流程与灰度第 2 版均已通过；配色已按用户反馈修订为 C2，等待用户审核。更新日期：2026-11-04。

本文件约定本次 UI 改版的设计范围、交付顺序和验收标准，不代表现有界面已经完成改版。用户已通过文字流程和灰度稿，当前交付 [配色方案 C2](ui-color-c2.md) 供审核；正式前端改造尚未开始。灰度阶段记录见 [灰度稿审核说明](ui-grayscale-review.md)。

## 1. 设计目标

- 视觉锐利、严肃、秩序明确，以考试任务为中心。
- 建立 3–5 个主色族，每个主色族包含 8–10 个色调，并形成可复用的设计变量。
- 先完成主要子页面的无彩色灰度 HTML 最小 demo，经用户审核通过，再制作配色 HTML 最小 demo。配色稿也须经用户审核通过，方案才算通过。
- 按学生参考、教师组织考试与阅卷、管理员支撑考试的实际业务设计；界面状态和操作沿用现有权限、考试及成绩规则。

## 2. 信息与视觉层级

考试相关元素也需要区分权重，避免所有考试信息同时抢占注意力。

| 层级 | 典型内容 | 设计规则 |
|---|---|---|
| 异常时的最高优先级 | 答案保存失败、时间即将耗尽、作答权限变化 | 在操作附近明确呈现原因与下一步；正常时不占用最高视觉权重 |
| 当前核心任务 | 学生题干与答题区、教师当前待阅答案与评分区 | 给予主要空间、最清晰的阅读顺序和充足对比 |
| 考试控制与进度 | 开始／继续考试、倒计时、保存状态、答题卡、交卷、发布或公布结果 | 始终容易找到；每个主要任务区域明确一个主动作；交卷与翻题分区，减少误触 |
| 决策信息 | 考试时间、时长、剩余次数、未答数量、阅卷进度、成绩状态 | 靠近对应动作，以稳定位置、文字和数字建立层级 |
| 支撑信息 | 全局导航、筛选、账号资料、一般统计、系统管理入口 | 保持可用与可读，视觉权重低于当前考试任务 |

学生首页优先呈现可继续、可参加、即将开始的考试；教师首页优先呈现需要处理的考试与阅卷任务。作答页以题目为中心，导航收敛；阅卷页以答案、评分依据、给分操作为中心。成绩页清楚区分最终成绩、各次成绩与待批改状态，遵循“最后一次有效提交”的既有规则。

形式上采用明确的栅格对齐、清晰分隔线、克制的字体层级和小圆角。灰度阶段初拟 0–4 px 圆角，不使用装饰性渐变、弥散光晕和大面积阴影。按第一轮评审，下拉浮层使用克制阴影表达层叠，加载占位条使用短白色渐变扫光表达加载状态。严肃感通过秩序和边界表达，正文保留舒适的字号、行距和留白。

## 3. 页面覆盖范围

以当前 `frontend/src/router.ts` 与角色操作指南为依据。相似页面可以共用模板，但在 demo 内提供明确的页面或状态入口。

| 页面组 | 灰度 demo 覆盖 | 重点验证 |
|---|---|---|
| 角色首页 | 学生首页、教师首页；管理员沿用角色化框架 | 考试和阅卷待办优先于通用统计与管理入口 |
| 学生考前 | 考试列表、考试详情 | 状态、考试条件与开始／继续入口 |
| 学生考中 | 作答页、交卷确认、提交完成状态 | 题目、答题卡、倒计时、保存反馈及交卷层级 |
| 学生考后 | 成绩列表与详情、答卷回看 | 最终成绩与各次成绩、待批改与未公布、回看权限 |
| 教师考试管理 | 考试列表、考试详情及配置／名单区域 | 草稿、发布、进行中、结束、结果公布的操作区分 |
| 教师备考 | 题库及题目编辑、试卷列表及组卷编辑 | 题目阅读、选择、排序、分值与发布前检查 |
| 教师阅卷 | 阅卷任务列表、答卷评分页 | 待办、原答案、评分依据、分值与完成操作 |
| 学习反馈 | 错题列表及详情、学习分析 | 题目复习与数据阅读层级，避免图表压过任务 |
| 支撑页面 | 登录、账号管理、班级管理、审核、系统日志 | 表单、表格、筛选、反馈和危险操作的统一规则 |

注册、联系方式、修改密码与申请进度采用共用表单／反馈模板，在灰度 demo 中提供代表状态；如发现独有布局或关键操作，再补独立视图。

制作顺序：先完成“考试列表 → 考试详情 → 作答 → 交卷”核心链路，再复用已建立的结构补齐其余主要页面。全部约定范围通过灰度审核后，才能进入配色阶段。

## 4. 工作流程与审核关口

| 阶段 | 主要工作 | 交付物与进入下一阶段的条件 |
|---|---|---|
| 0. 文字流程评审 | 对齐目标、页面范围、任务层级、交付格式和验收方法 | 本文件；用户已通过 |
| 1. 灰度结构设计 | 确定框架、版式、文字、间距、边框、圆角及任务顺序；完成核心链路后覆盖主要页面 | 一个可直接打开的灰度单文件 HTML |
| 2. 灰度审核与修订 | 用户审查页面结构和重点；记录问题并在灰度稿中修订 | 用户明确通过灰度稿；未通过时继续修订灰度稿 |
| 3. 色板与语义设计 | 在已通过的结构上制定主色族、色阶、状态语义及组件映射 | 色板说明、色阶表、语义变量表；不擅自改变已通过的页面层级 |
| 4. 配色 demo 与视觉验证 | 将色板应用到同一组页面、相同示例内容和状态；校验对比、交互和视觉重量 | 一个独立的配色单文件 HTML，并保留已通过的灰度稿用于比较 |
| 5. 配色审核与方案定稿 | 用户审查整体气质、考试重点和状态辨识；按反馈修订 | 用户明确通过配色稿后，输出正式设计规范与落地清单，方案才算通过 |

审核按“页面／状态、问题、修改建议、处理结果”记录。若配色阶段发现需要改变信息顺序、主动作位置或主要布局，相关部分回到灰度审核后再同步到配色稿。局部色阶与对比调整在配色阶段完成。

正式前端实施另列为后续任务，依据已通过的方案更新设计变量、基础组件和页面；设计方案通过不等于生产界面已完成改造。

## 5. HTML 最小 demo 的交付规则

- 灰度稿和配色稿各为一个独立 HTML 文件，CSS、脚本及必要图标内联；无需安装依赖、启动后端或联网即可打开。
- 单文件内用页面选择器切换角色、子页面和关键状态。评审控制区与产品界面清楚分隔。
- 使用固定的虚构考试数据；题目示例覆盖短文本、长题干、公式与图形占位、单选／多选和简答，保证阅读与布局验证有效。
- 灰度稿只使用黑、白和中性灰，实际颜色满足 R=G=B。状态通过文字、边框、符号和填充区分；图标及图形也保持无彩色，不能仅给彩色界面套灰度滤镜。
- 保留足以评审的轻量交互：切换页面、筛选代表状态、选择答案、跳转题号、标记待检查、展开交卷确认、输入评分。所有操作只影响本地演示状态。
- 核心状态包括默认／悬停／焦点／选中／禁用，以及考试未开始、可开始、可继续、时间预警、保存中／成功／失败、未答提醒、提交完成、待批改和结果未公布。另提供代表性的加载、空态、错误、长内容和受限访问状态。
- 电脑端优先，以 1440 px 和 1280 px 检查主要版式，以 390 px 检查窄屏重排；检查长页面滚动时题目、倒计时及操作区的可用性。

已通过的灰度交付位于 [`design/ui-redesign/grayscale.html`](../design/ui-redesign/grayscale.html)，独立配色稿位于 [`design/ui-redesign/color.html`](../design/ui-redesign/color.html)。两者均可直接离线打开，灰度基线保留用于对照。

## 6. 配色阶段的方法

C2 采用清亮蓝、松绿、琥珀、暗红 4 个主色族，每族 10 个色阶。中性灰另设 10 阶，用于文字、边框、局部分区和不可答状态，不计入 4 个有彩色主色族。根据用户反馈，增加整个画面的白底比例、减轻灰底与深色块。完整 HEX、组件映射及实测对比度见 [配色方案 C2](ui-color-c2.md)。

4 个主色族分别承担核心操作与选中、成功确认、预警、错误与危险操作的职责。色板中的“主色族”不意味着它们在每个页面都有相同面积；常态界面由中性色承载，考试核心操作采用统一强调色，预警与错误色按状态出现。

每个色族先建立由浅至深的色阶（10 阶可记为 50、100、200、300、400、500、600、700、800、900），再逐阶校正明度、饱和度和实际对比。浅阶用于轻背景，中阶用于边界和控件，深阶用于强调文字或深色填充；具体可用组合须在 HTML 中验证，不能仅按编号推定可读性。

建立“基础色阶 → 语义变量 → 组件应用”的映射。例如：

| 语义用途 | 组件应用 |
|---|---|
| 页面背景、表面、分隔、正文、次要文字 | 页面、面板、表格、表单 |
| 主要操作、选中、键盘焦点 | 开始／继续考试、答题选项、当前题号、按钮 |
| 保存成功、时间预警、保存失败 | 保存反馈、倒计时、异常提示 |
| 危险操作、受限或禁用 | 取消考试、不可操作按钮及原因说明 |

不得把所有考试元素都涂成强调色，也不能用同一种视觉处理混淆“当前题”“已答”“待检查”“未保存”。图表复用已定义色族，并结合线型、符号或直接标签表达差异。

## 7. 验收标准

### 灰度审核

- 首屏可以清楚回答：当前处理哪场考试、当前状态是什么、下一步该做什么。
- 去掉彩色后仍能辨识主次；题目／答案区域是核心，导航、账号和一般统计不会抢占注意力。
- 倒计时、保存结果、未答数量和交卷入口容易找到；正常状态不持续压过题干，异常状态能够被注意。
- 开始考试、交卷、发布考试和公布结果的含义与位置明确；不能因强调考试而把不同业务动作混为一谈。
- 长题干、表格、弹窗和窄屏不会出现重叠、裁切或整页横向溢出；必要的数据表可局部横向滚动。
- 完成约定页面与代表状态，用户明确认可布局、层级和严肃感后，灰度阶段通过。

### 配色审核

- 提供完整的 3–5 个主色族、每族 8–10 阶色表，注明色值、用途及经验证的前景／背景组合。
- 已通过的灰度层级保持成立，考试主任务更清楚，状态色仅在需要时增强提示。
- 以普通正文对比度至少 4.5:1、关键控件边界与焦点对比至少 3:1 作为本次项目验收目标，使用实际相邻背景计算；静态色板好看不能代替页面验证。
- 不仅依赖颜色表达成功、错误、选中或作答进度；键盘焦点清晰，状态文字可读。
- 在相同数据、页面状态与窗口宽度下比较灰度稿和配色稿，并检查常态及预警／失败场景。
- 用户明确认可配色 demo 后，设计方案通过。
