# UI 视觉设计规范与 C3 主题标准

本文档定义了 **在线限时考试系统** 当前正式生效的 **C3 视觉设计体系**、五级界面信息权重、十阶色彩语义映射、全站 30 个页面布局规范以及前端视觉验收标准。

---

## 一、核心设计理念

考试系统不是花哨的营销落地页，我们的视觉设计围绕四个词展开：**锐利、严肃、秩序明确、任务优先**。
- **浅灰画布衬托纯白内容**：去掉装饰性渐变、弥散发光和大面积浮夸阴影。全局工作区采用极浅冷灰画布（`#F6F7F9`）衬托纯白内容面板（`#FFFFFF`），让学生的题干与作答区、教师的待批答卷与打分区永远处于视觉中心。
- **克制而硬朗的几何边界**：左侧导航栏按钮与左侧 `3 px` 选中指示条采用 **严格直角（`0 px` 圆角）**；内容卡片与普通控件采用 `0 ~ 4 px` 小圆角；输入框获得焦点时直接高亮自身内边框（不加外圈双重光环）；下拉弹出层仅用克制阴影表达层级，加载骨架屏采用 3.2 秒周期的短白光横扫动画。

---

## 二、五级界面信息权重（什么最显眼？）

在一场紧张的限时考试里，如果页面上所有按钮和标签都涂成五颜六色，反而会让考生抓不住重点。我们将界面元素严格划分为 5 个优先级：

| 视觉优先级 | 典型界面内容 | 设计处理规则 |
| :--- | :--- | :--- |
| **1. 异常与紧急预警**<br>（仅在发生时最高） | 答案保存失败、考试时间即将耗尽、多页面接管冲突 | 在操作区紧邻位置用暗红或琥珀色醒目提示原因与下一步操作；**正常答题时绝不常驻占用最高视觉权重** |
| **2. 当前核心任务区** | 学生的题目正文与答题框、教师的待阅学生答案与打分框 | 分配最大的版面空间、最舒适的字号行距与最高对比度 |
| **3. 考试控制与进度** | 开始/继续考试、倒计时、已保存状态、答题卡、交卷、发布考试/公布结果 | 位置固定好找；每个任务区只设一个蓝色主按钮（`#2164CE`）； **“交卷”与“上一题/下一题”严格分区，防止手滑误触** |
| **4. 辅助决策信息** | 考试起止时间、时长、剩余次数、未答题目数、阅卷进度、成绩状态 | 紧挨着对应操作按钮，用清晰的标签与等宽数字展示 |
| **5. 全局支撑信息** | 左侧主导航、列表筛选栏、个人账号资料、常规统计、管理后台入口 | 保持清晰可读，但采用低饱和中性色，绝不喧宾夺主 |

### 各角色核心页面布局重心
- **学生首页 (`StudentHomeView`)**：一上来先看 **“当前考试卡（右侧独立浅蓝只读倒计时区）”**，紧接着是 **“接下来的考试 / 学习记录双栏”** 与底部考试提醒，不堆砌无关账号大卡片。
- **考试详情页 (`StudentExamDetailView`)**：顶部展示“考试状态、作答时长、试卷结构”三张横向信息卡（统一采用普通细边框，不加顶部彩色粗条；考试结束后整排卡片转为中性灰不可答状态），下方展示纵向详细信息行与规则步骤。
- **学生专注作答页 (`StudentAttemptView`)**：隐藏左侧全局导航栏，顶部紧凑展示姓名、学号、截止时间、倒计时与“退出作答界面 / 交卷”按钮；主体采用 **左侧题目主栏 + 右侧 `268 px` 答题卡** （窄屏可折叠）。退出时弹窗明确提醒“退出不会暂停计时，到点将使用服务器已保存答案自动提交”。
- **教师专注评分页 (`StaffAttemptView`)**：同样隐藏全局侧栏，采用 `1248 px` 居中工作区（ **左侧主栏** 展示题干、灰底左线学生答案、参考依据与评分历史；**右侧 `300 px` 侧栏** 放置打分/改分表单与答卷进度）。
- **管理员职责隔离**：管理员界面移除一线“阅卷工作台”和直接打分入口，专注于账号管理、教学班、学生审核、系统日志以及考试详情里的 **“阅卷进度监控与异常任务改派”**。

### 2. 关键组件用色映射规则

| 界面对象 | 前景 / 文字色 | 背景 / 边框色 | 视觉与交互规则 |
| :--- | :--- | :--- | :--- |
| **工作区与面板** | Neutral 900 (`#202020`) | 画布 Neutral 50 (`#F6F7F9`)；面板与侧栏纯白 `#FFFFFF`；分隔线 `#E5E5E5` | 浅灰衬底凸显纯白内容卡片层次 |
| **主操作按钮** | 纯白 `#FFFFFF` | 默认 Blue 600 (`#2164CE`)；悬停 `700`；按下 `800` | 开始考试、保存、提交等当前核心主动作（对比度 `5.56:1`） |
| **侧栏选中导航项** | Blue 700 (`#1A50AA`) | Blue 50 (`#F2F7FF`) 背景 + 左侧 `3 px` Blue 600 直线条 | 按钮严格 `0 px` 直角，对比度 `7.04:1` |
| **输入框与下拉框** | Neutral 900 (`#202020`) | 默认边框 Neutral 500 (`#8C8C8C`)；焦点内边框 Blue 600 (`#2164CE`) | 焦点只强调自身边框，下拉弹出列表带克制浮层阴影 |
| **答题卡题号状态** | 当前题：白字；已答：Blue 800 | 当前题：Blue 600 实心底；已答：Blue 100 底 + Blue 500 边框 | 一眼区分“当前正在答的题”、“已答题”与“未答题” |
| **“已标记待检查”按钮** | 纯白 `#FFFFFF` + 实心白旗 | 专用深灰底 **`#3A3A3A`** （常态为浅灰底 + 空心旗） | 与蓝色主操作和琥珀色时间预警严格区分（对比度 `11.37:1`） |
| **保存中 / 已保存** | 已保存：Green 700 (`#1C5038`) | Green 50 (`#EDF7F2`) 底 + Green 500 边框 | “正在保存”显示旋转 spinner 图标，完成后才切换为绿色对勾 |
| **时间预警 / 保存失败** | 预警：Amber 800；失败：Red 700 | 预警：Amber 50 底 + 600 边框；失败：Red 50 底 + 600 边框 | 同时配文字原因与重试按钮，不单靠颜色表达状态 |

## 四、全站 30 个页面场景设计与数据适配准则

系统全部 30 个页面场景（学生端 11 页、教师与管理员考试阅卷 6 页、题库组卷与系统管理 8 页、公共与账号 5 页）均已按上述规范落地，并遵循以下工程适配原则：

1. **核心组件统一复用**：所有页面统一使用 `PageHeader.vue`（英文眉题 + `30 px` 主标题 + 右侧主操作）、`SurfacePanel.vue`（纯白卡片容器）、`AppSelect.vue`（统一 CSS 下拉与键盘可访问性）和 `LoadingSkeleton.vue`（3.2 秒白光横扫骨架屏）。
2. **坚持真实接口边界，绝不伪造展示数据**：
   - 考前详情接口不提前暴露题目明细，因此“试卷结构”卡只展示真实总分，并诚实提示“题量与题型进入作答后查看”。
   - 成绩列表与详情严格遵循“最后一次有效提交”口径；未公布或待批改状态显示 `—` 与中性灰说明，绝不按 0 分渲染。
   - 注册与修改密码页面的独立“密码要求”说明栏统一放置在密码输入框与提交按钮之间。
3. **无障碍对比度与多端尺寸要求**：
   - 普通正文对比度不低于 **4.5:1** （次要文字 `#626262` 在 `#F6F7F9` 画布上实测为 `5.69:1`），控件边框与焦点对比度不低于 **3:1**。
   - 同时适配 **1440px / 1280px 桌面端** 与 **390px 移动端**，宽表格在自身容器内横向滚动，严禁出现整页水平溢出。

## 五、UI 与交互自动化验证命令

修改前端样式、布局或共享组件后，可在 `frontend/` 目录下运行内置的 C3 视觉与布局专项 Playwright 测试套件（基于固定接口快照运行，无需启动后端）：

```bash
cd frontend

# 1. 运行 C3 基础组件、主题色值与关键状态交互验证
npx playwright test \
  tests/e2e/c3-foundation.spec.ts \
  tests/e2e/c3-content.spec.ts \
  tests/e2e/c3-student.spec.ts \
  tests/e2e/c3-implementation.spec.ts \
  tests/e2e/c3-review-details.spec.ts \
  --workers=1

# 2. 运行全站 30 个页面布局与响应式验证
npx playwright test \
  tests/e2e/student-home-design.spec.ts \
  tests/e2e/student-pages-design.spec.ts \
  tests/e2e/staff-exam-pages-design.spec.ts \
  tests/e2e/content-admin-pages-design.spec.ts \
  tests/e2e/public-pages-design.spec.ts \
  --workers=1

# 3. 检查 TypeScript 编译与代码格式
npm run build
npm run format:check
```
