六条后台可靠性用例最终组合回归：`uv run python -m pytest -q --tb=short tests/test_attempt_recovery_http.py`，**6 项通过，55.50 秒**。行为矩阵如下：

| 行为 | 实际证据 |
|---|---|
| 数据库已提交、ARQ 队列不可达 | HTTP 开始／保存成功；截止前读取已保存答案；独立 worker 启动扫描结果包含该作答 ID，HTTP 返回 TIMEOUT／PENDING 收据 |
| Redis 不可达的重复运维恢复 | 仅依赖 PostgreSQL 的 `recover-attempts` 再执行，提交数为 0，时间与次数不变 |
| 真正的定时截止任务 | worker 在截止前启动，一次性模式不创建 cron；截止任务的公开 ARQ `Job.result()` 为 true，HTTP 有效提交时间等于 deadline |
| 重复任务 | 同一已提交作答再触发两份任务，公开结果均为 false，提交时间及已用次数不变 |
| 撤销资格后显式恢复 | 原作答仍 VOID，旧截止任务结果为 false，已用／废弃次数均为 1 |
| 整场取消 | 旧截止任务结果为 false，原作答仍 VOID，已用／废弃次数均为 1 |
| 停用学生账号 | 正常定时任务仍提交；恢复账号后经真实登录读取 TIMEOUT／PENDING 收据，原 deadline 和次数未重置 |
| 常驻周期补偿 | 入队不可达且 worker 在截止前启动；默认每 30 秒 cron 的公开结果包含该作答 ID，再读取 HTTP 收据。不能由 HTTP 自动收尾替代该后台证据 |
