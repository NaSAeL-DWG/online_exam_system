# 迭代 4 接口契约

日期：2026-10-07。状态：实施中，以下是前后端与 worker 的协作约定，实际实现及测试完成后复核。

依据：[需求规格](./需求规格.md)、[数据库表结构](./数据库表结构.md)、[后端架构设计规范](./后端架构设计规范.md)。本轮实现判分、阅卷和教师侧最终成绩查询；学生成绩公布、历史回看、错题和分析仍属于迭代 5。

## 业务约束

- 单选／判断完全正确满分，多选支持 EXACT／PARTIAL，使用 Decimal 按四舍五入保留一位小数；空白简答自动零分，判断 false 不视为空答。
- 提交事务完成后投递自动判分，数据库扫描补偿队列丢失或投递失败。考试结束并完成到期提交、客观题及空答判分后，按整份答卷均分人工任务。
- 首次整卷完成前仅指定且激活的教师可评分；整卷首次完成后其他激活教师也可改分。管理员通过改派处理首次阅卷，不绕过该规则。
- 更正仅使受影响题目的评分失效，无关题分保留。考试与单题评分版本防止迟到任务覆盖新依据；简答重开任务保留首次整卷完成事实。
- 资格撤销／整场取消同事务废弃作答和任务，恢复资格不复活旧作答。教师停用保留已评题分，未完成任务等待改派。
- 最终成绩先取最后一次有效提交，再判断是否已判完；待批改不能回退至上一次分数，也不能当作零分。
- 已公布结果必须先撤回才能改分或更正依据；本轮提供必要撤回能力，完整公布与学生结果读取后续实现。现有学生收据及图片接口继续防止提前泄露成绩和评分依据。

## HTTP 接口约定

以下路径均以 `/api` 为前缀。教师及管理员读取共享资源，写请求检查 CSRF；管理员改派使用管理员路径。列表沿用 `page`、`page_size` 与 `items`、`total` 分页契约。金额／分值使用十进制字符串。

| 方法／路径 | 用途／关键输入 |
|---|---|
| GET `/staff/exams/{id}/attempts` | 考试有效提交答卷列表 |
| GET `/staff/attempts/{id}` | 答卷、逐题评分、任务状态和操作权限 |
| POST `/staff/answers/{id}/grade` | `version`、`grading_revision`、`score`、`comment`、`reason`；返回更新后答卷 |
| GET `/staff/answers/{id}/history` | 不可变评分历史 |
| GET `/staff/grading-tasks` | 按考试、状态、指定教师筛选整卷任务 |
| POST `/admin/grading-tasks/{id}/reassign` | `version`、`teacher_id`、`reason`；保留已有题分 |
| GET `/staff/exams/{id}/final-results` | 最后一次有效提交及其真实判分状态 |
| POST `/staff/exams/{id}/questions/{qid}/correct-standard` | 考试 `version`、题目 `grading_revision`、`standard_answer`、`explanation`、`reason` |
| POST `/staff/exams/{id}/withdraw-results` | 考试 `version`、撤回 `reason` |
| POST `/staff/exams/{id}/grading/refresh` | 人工触发判分／分配重试；不替代后台自动处理 |

详细响应字段和错误码待实现后对照响应 schema 补齐；目前不得将本表当作已交付证明。

## 后台公开业务能力

- `grade_attempt(session, attempt_id, grading_revision=None)`：判分一个有效提交，检查目标修订，重复触发不重复历史或覆盖人工评分。
- `assign_exam_tasks(session, exam_id)`：按考试事务锁分配待人工评分的整卷任务，不提前分配、不复制任务。
- `scan_pending_attempts(session, limit=100)`：取得待自动处理作答与目标修订。
- `scan_assignable_exam_ids(session, limit=100)`：取得结束后待分配／补处理考试。

写用例使用统一的身份（人工操作）、考试、资格、作答、任务、答案锁顺序。CRUD 不提交事务，HTTP 与 worker 调用公开业务用例，跨模块协作不直接访问其他模块的内部 CRUD。
